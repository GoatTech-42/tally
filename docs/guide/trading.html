QUICK ANSWER

“How do I make it only do specific items?”

  1. Open Items. Use the Items tab in GoNuts or the Items page in your bot’s web panel.
  2. Search and select your items. For example, select Diamond and Breeze Rod, then click Include.
  3. Review the Included filter. Include adds to the existing list. Remove any previously included markets you no longer want: select those entries and use Clear. Keep at least one included item while you want a restriction.
  4. Check Excluded too. Exclusion wins over inclusion. The Include action clears conflicting exclusions for selected items, but a broader category exclusion can still matter.
  5. Check the Flips mode. For automatic pricing of your selected markets, leave Flips only: OFF. For manual prices only, follow the Flips steps below.
An empty Included list means unrestricted automatic item selection. Clearing the last included item does not mean “trade nothing.” An empty Flips list with Flips only ON behaves differently: it waits for an entry.

Track and Include can both be used on the same item. Track watches the market; Include controls whether it belongs to your restricted allowed set. Neither forces a purchase if price, inventory, capacity or profit checks refuse it.

Save item loadouts

In the game, open B → Trading → Items → Item loadouts. Give the current item selection a name and save it. Keep separate sets for different markets, then select a saved loadout and choose Apply to switch manually. You can rename, replace, copy or delete a saved set; deletion asks for confirmation.

A loadout contains only Included, Excluded and tracked markets, including empty lists. Each saved set is an independent copy. It does not change trading limits, protections, positions or collection credits. Review the selected markets before resuming: exclusions still take priority, and all normal price, inventory and safety checks apply. General settings presets remain separate.

Exact items versus families

In Settings text lists, a name such as glass can match plain glass and names ending in _glass, including stained glass. Use =glass for only plain glass. Item IDs such as diamond and breeze_rod avoid spelling ambiguity.

Focus new buying

Keep broader Include and Track lists, then enable Settings → Advanced view → Items & focus → Use trading focus and set Trading focus items for new purchases and bids. Use comma-separated exact items such as =experience_bottle, =end_crystal. An enabled empty focus buys nothing. Exclusions, liquidation choices, spending limits, quote evidence and safety gates still apply. Existing stock and orders finish normally; focus does not cancel them or suppress broader price observations.

Save an Original preset before changing settings. You can save narrower Focused and broader Overnight presets and switch manually. There is no automatic overnight schedule or learned profit ranking, and a short trial does not establish a reliable profit improvement.

Upgrading and changing markets

The retired legacy purchase-focus list still migrates into Items Include and Track, retaining existing selections and explicit exclusions. This is separate from the new, visible optional trading focus. Include/Exclude restrictions also affect existing stock handling, so keep an item eligible while its goods are still being managed. Positions and pending actions are never erased by this conversion.

Set up Flips only

  1. Open Flips. In the game GUI or your bot’s web panel, open the Flips page.
  2. Enter an item, buy price and sell price. Prices are per item. Separate entries with commas or new lines.
  3. Save the list. Check for Not understood messages and correct them before continuing.
  4. Turn Flips only: ON. Verify that the page says general market scans are off. With it OFF, automatic markets are still allowed.
  5. Review the saved rows and current state. Check Item, Buy, Sell and Order up. Item inclusion/exclusion, account limits and native execution checks still apply.
diamond 5000 6500 x1
breeze_rod 1000 1400 x2

Syntax examples only—not current prices or trading recommendations. Replace these numbers with prices you have checked on the server. x1 means one stack for a stackable item, not one individual item.

Flips only turns off broad market discovery; targeted order quotes, reads of your own orders, collection, listing and maintenance of existing stock still run. Turning it on does not cancel a purchase already in flight or wipe existing inventory. A queued general scan is abandoned safely.

With Flips only ON and no entries, the bot waits for you to add an item. It does not silently switch back to automatic trading. To return to automatic markets, turn Flips only OFF and review Included, Excluded and new-purchase focus as well.

Prices and quantities

The basic form is item buy sell. Spaces are allowed in item names; IDs with underscores work too. Numbers accept suffixes such as 4k and 2m.

Order sizediamond 5000 6500 x3Requests three stacks per order, subject to limits. For nonstackable items, x3 means three items. For stackable items the order is capped at fifteen stacks.

The Flips page’s Bought and Spent figures belong to the entry’s configuration. Changing buy/sell prices, top-bid behavior, total or budget starts a new accounting signature. Do not repeatedly edit those values if you intend a limit to cover the same buying run. Removing an entry does not remove real stock or erase the ledger.

More than one buy order for an item

Under Settings → Advanced view → Orders, set Buy orders per item to 2 to allow two separate automatic orders for the same item on each account. This works in normal ordering with Reserve Stock off. Stacks per bid remains the ceiling for each order; changing the order count does not multiply the quantity of a single bid. Native sizing, live prices and existing safety limits still apply.

0 preserves existing behavior: one normal order, or two purchases in a Reserve Stock cycle. Existing accounts keep their settings at upgrade. Filled orders awaiting collection still count until their stock is collected; old completed rows already collected do not. A fresh native read separates placements. Held stock and both orders share the same depth and spending budget, and collection waits for room on the selling shelf. Lowering the count retains existing orders and prevents additional bids until they fit.

This is a maximum, not a promise that every market will qualify or fill immediately. Extra orders require a fresh, complete native own-order read. If the visible book is full, has unread rows or offers another page that has not been read, new spending waits rather than assuming the unseen orders are empty. The current exact-count protection still limits ordinary 64-item-stack orders to fifteen stacks, even if Stacks per bid is sixteen or higher. It does not claim exact 1,024-item support.

Reserve Stock: refill the shelf as stacks sell

Under Settings → Advanced view → Orders, turn on Reserve Stock. Set Buy orders per item to 2 and both Reserve batch stacks and Stacks per bid to 12 for two separate twelve-stack orders per automatic market. The explicit order count is configurable from 1 to 90 (0 preserves mode defaults); the account’s actual order capacity still applies. The mode is off by default. It uses order-house buying and whole-stack selling for automatic stackable markets; manual Flips retain their own quantities and rules.

  1. The desk places up to two buy orders of twelve stacks, with a fresh native read between placements. The first twelve stacks form the selling shelf; the other twelve remain on the order house.
  2. As whole stacks sell, the normal task queue collects only enough delivered whole stacks to refill the shelf. One vacant shelf slot means at most one replacement stack. Stacks already queued, in hand or being repriced count as shelf stock. Collection also waits for verified auction capacity and inventory room.
  3. Partial orders can supply delivered whole stacks; unfinished stacks stay on the order. Each top-up verifies the actual inventory change and rereads the order book before another collection.
  4. Once both the shelf and the uncollected or unfilled reserve are empty, the next cycle can buy another pair at freshly checked prices. A saved cycle record prevents early replacement purchases across restarts. Existing stock at upgrade is adopted and drained before a new pair is bought.

A full batch must fit the existing per-purchase, session, order-slot and market-depth checks. Twelve is a requested batch size, not a promise that every market qualifies. The total target is the configured number of batches including stock already held and outstanding or uncollected order quantities. This is a stock-cycle limit, not a promise that the configured number stays open continuously. The next cycle waits until its existing stock and orders drain. Reducing the count keeps existing orders and blocks further purchases until they fit. Filled reserves count at cost against the spending cap. Existing smaller orders and owned stock are preserved; no records or orders are cleared to force this layout.

All normal recovery, ownership, persistence and connection checks remain in control. Winding down can collect remaining goods through the existing cleanup flow. Turning the mode off returns to normal collection without deleting orders.

Stacks, singles and Underdog

There are three separate quantities: the order’s total requested amount, the amount delivered so far, and the size of each auction listing. One diamond delivered from a larger order is different from an order requesting one diamond.

Singles controls selling one item at a time. The Selling setting Singles up per market at once controls how many such listings can be up together. It does not set the buy order’s total.

Underdog is an automatic discovery feature that follows observed rival markets; it is not another name for Flips or singles. Its observed-market sizing path can choose one item when the observed lot is one item. That is one possible explanation for repeated x1 orders, not proof of the cause in every report. Switching on Flips only uses your manual markets instead of general discovery.

If you expect a larger order but see x1 repeatedly, record the order’s total requested amount and the listing amount separately. Include the running build, item, Flips mode, manual entry if any, and whether Underdog is enabled in your bug report. Do not assume a small delivery proves the original order was x1.

BALANCE IS NOT PROFIT

“My balance dropped. Did I lose money?”

First check your own orders in the order house. Money committed to an active buy order is no longer available in your spendable balance. When an order fills, that money becomes purchased goods, which may still be waiting to collect. A lower bank balance alone does not mean the bot lost that amount.

  1. Check the correct account. In a hive, inspect each bot separately. One account’s displayed bank is not the whole hive’s capital.
  2. Check Orders and the server’s own-order menu. Look for active orders with funds committed, and delivered items waiting for collection. An order’s unfilled portion and its delivered goods are different categories.
  3. Check stock and listings. Collected purchases may be in inventory or already listed on the auction house. They have a purchase cost even before they sell.
  4. Open Analyzer and review capital allocation. It separates available bank, observed order funds, delivered goods, unlisted stock, auction stock at cost and unresolved exposure. Check freshness and coverage notes; unknown or stale figures are not zero.
  5. Check completed sales for actual profit or loss. Compare recorded sale proceeds against recorded purchase cost. An unsold asking price is potential revenue, not money already earned or a guaranteed recovery value.
Example: You start with 10 million available. Later the bank shows 7 million, active orders hold 2 million, and purchased stock cost 1 million. That accounts for the 3 million bank decrease without proving a 3 million loss. This simplified example is not a valuation of what the stock will eventually sell for.

Do not add the same funds twice. An order payment that becomes delivered stock is no longer both spendable money and stock. Analyzer uses observations with limits; it is not a guaranteed complete net-worth statement. Real losses can still happen, so investigate unexplained differences instead of assuming everything is safe.

If money or goods remain unaccounted for after fresh own-order, inventory and listing checks, send a bug report with the approximate time, affected item and expected versus observed amounts. Do not reset the ledger, delete the database or cancel every order to try to make the numbers match.

Save a setup, then use Analyzer

  1. In Settings, use Saved presets to save your current setup under a recognizable name.
  2. Make one change at a time so you can understand its effect. Applying a preset changes current settings; it does not rewrite the saved copy.
  3. Open Analyzer to inspect the account’s recorded ledger, capital, capacity and observations. Check the evidence and any stale or unknown categories.
  4. A suggested preset is saved for review. It does not apply itself or start trading.

Bank balance, funds committed to orders, unlisted goods, listed cost basis and realized profit describe different things. Asking value is not realized profit. More sales per hour can coincide with less profit per hour if the sales mix earns less per sale or older high-profit sales leave the rolling window. A rising player count or spare listing slots alone does not establish the cause.

Your Hive and the wider Swarm

Read the full Swarm joining, benefits and privacy guide.

Your Hive groups your own bots. The Swarm includes participating bots across users. Local hive database setup and linking bots to the hosted dashboard are separate steps; see the hive setup guide.

  1. Open the dashboard and sign in with Discord.
  2. Choose Link client for a fresh pairing code. In the bot’s Dashboard linking page, choose the intended account and enter its code. Use a fresh code for each bot.
  3. Read the linking disclosure: linking opts that bot into contributing observed public market/follow activity and receiving discovery hints. Unlinking leaves Swarm participation.
  4. Check each card’s own state. The anonymous Swarm total counts distinct participating bots with an upload in the last ten minutes; it does not expose their identities or other users’ cards.

Each mascot animates independently. Antenna activity represents actual reported send/receive transport events, not completed trades or proof that a game scan was avoided. Older builds without transport telemetry cannot show those events. Shared observations help discovery; current native price, inventory, own-order, capacity, profit and guard checks still decide execution.

Common questions

Does “12 stacks per bid” mean 12 items? Why did a filled order produce 7 or 8 items?

No. Twelve stacks of a 64-stack item means up to 768 items. Automatic sizing may ask for fewer whole stacks based on market evidence, spending limits and listing room. With single-item selling off, an unsupported or unaffordable whole stack is skipped rather than replaced with a few items. A fixed bug had counted single-item price samples as stacks and allowed a cap-driven fallback to singles; update to the PR #164 client or newer.

“Fully filled” describes the quantity requested by that order. An old order requesting 7 items is complete when 7 arrive. Existing orders and stock are preserved after updating, so those older small lots can still finish. Collection may also retain legitimate remainder handling; it does not rewrite an order into full stacks. Explicit single-item selling is a separate mode. Do not raise limits or clear inventory to force twelve stacks.

I clicked Track, but it still trades other items

Track is the watch list. Use a nonempty Included list to restrict automatic markets, or Flips only ON for only your manual price entries. Review any old Included entries too.

I added Flips, but it still chooses other markets

Check that Flips only is ON and saved. OFF deliberately allows Flips alongside automatic markets. Existing stock maintenance can continue even after you change the mode.

My selected item never gets bought

Check Excluded, Included, new-purchase focus and Flips mode together. Then check spelling, saved-row errors, current quote, budget, balance, inventory and available capacity. In a hive, market assignment can also put that market on another account. Being included means eligible, not guaranteed to buy.

I have free auction slots. Why aren’t they all used?

Capacity is a ceiling, not a target. Eligible supply, order fills, held stock, per-market listing limits and trade checks can leave slots empty. Read the current state before changing sizing or risk limits.

My bank balance fell. Has the bot lost money?

Check funds held in active buy orders, delivered goods waiting to collect, and purchased/listed stock first. Bank balance is available cash, not all capital. Then check recorded completed sales and any unexplained difference. Follow the balance checklist and example.

Profit per hour fell while sales per hour rose

Compare profit per sale and which items sold in the same rolling window. More low-margin transactions can replace fewer high-margin transactions. Check Analyzer and the ledger; the two counters alone cannot identify a failure or prove Swarm caused the change.

It is paused or seems stuck

Read the pause reason and recent events in Status, Evasion and Staff Watch. A protective pause is different from a manual pause. Do not clear positions, reset the ledger or override a guard just to make the status change. Report a sustained unexplained state with its time and diagnostic evidence.

The web panel stays on Reading…

Check that the actual running client is the latest build, not merely that a new JAR downloaded. Reload the panel. If Report bug in the web panel is unavailable, use the in-game About → Report bug route and describe the affected panel page.

Send a useful bug report

Use About → Report bug inside GoNuts, or Report bug in a working web panel. Include what you expected, what happened, the item and the approximate time. For sizing issues, distinguish requested, delivered and listed quantities.

Sanitized diagnostics are included automatically. Preview them if desired, then send and wait for the submitted issue link. Reports are public: do not put tokens, pairing codes, home names or other private information in your description. A Discord ping can be missed; a submitted report gives support a diagnostic record.
